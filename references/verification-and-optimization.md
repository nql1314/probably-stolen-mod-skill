# 验证与优化决策

适用于编译、运行异常、游戏更新和性能/可靠性优化。先定位故障阶段，再选择能回答具体问题的检查；本指南的验收项不自动授权启动游戏、安装或发布。

## 按阶段定位

| 阶段 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 文档/静态检查 | 引用、类型/签名、分支与数据流是否一致 | 实际补丁安装、原生语义、帧耗时 |
| 编译 | 所选引用下类型和构建约束通过 | 产物已部署或被当前进程加载 |
| 打包 | 发布目录包含预期产物与依赖 | 已安装、运行时用的是这份文件 |
| 安装/加载 | 正确位置与当前进程实际加载版本 | 玩法正确、迁移和保存重载成功 |
| 玩法运行 | 给定构建/状态/操作下观察到行为 | 全部边界、其它版本和存档往返 |
| 保存重载 | 对应状态在指定路径下能往返 | 所有旧版本、回档和另存路径 |

普通代码修改默认编译相关项目并运行必要的已有检查；先检查构建脚本是否默认安装。用户未要求打包或安装时，不自动整理发布包或覆盖游戏目录。依赖公共框架的调用者应使用同一份匹配产物；API变化同步受影响调用点与构建入口。

## 游戏更新与“没生效”

确认本次 AppID/分支/Steam Build、内部版本、后端、加载器、互操作引用、产物路径和日志所属进程。这些标识含义不同，不能仅修改一个版本常量就称适配完成。

按顺序确认：文件位置→程序集身份/依赖→入口执行→目标解析→补丁所有者与实际安装→就绪门控→触发链→权威写入→显示刷新。只看到补丁特性或启动横幅，不能跨过后面的步骤。

复用旧实现前，将接口标为“当前材料支持”“旧版专用”“已确认不适用”或“尚未核实”，同时记录参考产物和完整签名。包日期、程序集版本差异或仍能反射到类型，都不足以判定可用性；检查它是否仍有实现、是否进入当前挂接链，以及原有配置是否还有消费端。旧兼容入口、空方法和已拒收的数据格式不作为当前默认示例；替代入口也须核对所需语义。互操作程序集与原生构建未确认对应时，成员存在只能说明该静态快照支持声明。

二进制兼容要比较已编译调用的完整成员签名。新增可选参数方便重新编译后的调用，不会自动补齐旧 DLL 的参数；只看同名方法仍存在会漏掉这种失配。反射还要核对字段与属性：IL2CPP 互操作层可能用属性访问原生字段，同名 `Field` 查找无法代替属性 getter。替换入口后仍须检查调用时机、类型与业务副作用。

保留既有未提交改动。常规修改不创建时间戳备份、全量哈希或额外报告；需要确认产物一致性时再做针对性比较。已有日志须能对应构建、产物和进程；无法对应则注明历史范围。

## 优化如何排序

先读自己的目标实现和真实工作负载。优先处理有具体证据的数据丢失、重复写入、错误恢复和越界，再处理实测热点；第三方做法只能提供核查方向，不证明本地项目已有同样问题。

| 观察到的问题 | 候选改变 | 采用前的关键检查 |
| --- | --- | --- |
| 每帧重复全量展示计算 | 事件脏队列、软预算巡检、按需属性写入 | 事件是否齐全、缓存失效与巡检公平性、单项最坏成本 |
| 多步写入失败后状态不一致 | 复用原生完整操作，或计划/预留/回执/补偿 | 原生返回语义、部分成功、异常后对账能力 |
| 嵌套/异常留下临时标记 | 调用级状态与单次释放 | 正常、异常、重入、清理本身失败 |
| 列表重排后选错对象 | 稳定ID选择与提交时重新解析 | 删除项、重复ID、读取旧存档 |
| 同功能通过多个入口触发 | 共同资格函数、操作级去重 | 不能把帧号当业务身份；保留独立合法操作 |
| 依赖失配拖垮整包 | 精确能力探测与功能级就绪门控 | 真正必需依赖不能被静默降级成假成功 |

建议写清目标、当前证据、预期收益的依据、改动代价、风险/依赖与下一验证动作。没有测量时不填提升百分比；软截止和限步常量不是性能提升证明。一个局部补丁无需为“设计模式”增加事件总线、通用事务框架或多层抽象。

检查通过后停止。只在新改动影响结果、检查失败或有具体疑点时重跑；文案/简单样式不新建测试，不编写只复述实现的测试。

## 按真实复杂度选择结构

| 需要解决的问题 | 可采用的职责划分 | 何时无需增加这一层 |
| --- | --- | --- |
| 多条同形内容有不同参数 | 数据定义 + 注册表/工厂，行为只处理共同规则 | 一个固定数值补丁直接沿用现有配置 |
| 同一资格同时被预览、提交、自动化使用 | 纯判据与有副作用的执行分开 | 只有一个简单入口时保留局部函数即可 |
| 大量重复展示事件 | 合并脏事件 + 有配额的刷新队列 | 元素少、事件稀疏时直接刷新 |
| 嵌套调用临时改变上下文 | 调用级令牌/作用域 + 单次释放 | 单次同步局部操作用普通try/finally |
| 不同版本/宿主提供可选能力 | 小范围适配器 + 明确能力探测 | 只支持一个确定接口时不做泛化兼容层 |
| 跨天/跨次加载完成履约 | 持久状态机 + 业务身份 + 回执 | 同一原生事务能完成时直接复用 |
| 复杂UI观察权威状态 | 派生展示模型 + 明确失效 | 简单标签直接从权威数据读取 |

结构的价值是明确谁负责判断、执行、保存与清理。名称只用于沟通；不按某个模式名称反推项目必须重构。

## 原生测试触发规则

只有用户明确要求执行 Probably Stolen/Nicokobo Forge 原生测试，或显式点名相应原生测试技能时，才读取当前环境的 `probably-stolen-native-test` 技能并按其要求执行。对象不明时先澄清，不启动游戏。

讨论测试、引用触发语句、整理技能、普通开发/修复/编译均不触发。没有可用测试技能或游戏环境时保留明确验收计划，不把未执行项目写成通过。
