# 状态、存档与迁移

适用于周目进度、跨日生产、订单、统计和物品附加状态。先区分游戏权威数据、Mod权威进度、可重建索引与临时UI；恢复失败时允许丢弃哪一类必须明确。

## 身份与寿命

存档槽是存放位置，周目身份是业务身份，原生实例/指针只是本次加载对象。新局、普通读档、回档、复制到新槽和周目分叉不能只靠槽号或当前日号混成同一路径。

| 路径 | 应核对的行为 |
| --- | --- |
| 新局 | 只初始化一次，不能继承旧槽的外部进度 |
| 同周目普通读档 | 清临时上下文/指针缓存，再从所选快照恢复 |
| 读更早存档 | 派生状态随档回退，不能把外部较新完成标记套上去 |
| 另存新槽 | 明确是否延续同一业务身份，更新寻址但不重复发放 |
| 周目分叉/新逻辑身份 | 按产品规则复制或重置；不要仅按两个ID不同猜测是新局 |

稳定命名空间键与格式版本用于持久化；业务规则变化需要版本迁移，不依赖程序集版本自动推断。

## 保存位置与写入时机

优先使用当前项目支持、确实随游戏存档走的扩展字典或物品字段。若需在原生序列化前写入状态，确认所有有效保存路径都经过该入口；仅存在 SaveGame Prefix 不证明它覆盖自动保存、另存与其它保存入口。不要另建一套与已有公共存档机制重叠的系统。

必须外部文件时，绑定明确的周目/快照身份，并先验证新内容再替换。临时文件+重命名只处理单文件更新，不使游戏存档和外部文件组成同一个事务。定义崩溃后、游戏保存失败后及回档后的对账策略。

保存后的检查点应在确认游戏写入完成后制作，按槽或周目区分并限制保留数量。覆盖当前文件前的恢复保护副本则保留覆盖前的数据；两者不能混用。备份成功不等于恢复可用，恢复还涉及索引、当前游戏状态及重启/读档时机。

恢复时先验证所选快照存在、可读且身份匹配，再制作本次覆盖所必需的保护副本，并检查结果；这些步骤成功后才能替换当前存档。无效选择不应提前覆盖已有恢复点，保护副本失败也不能静默继续。失败后是否允许原生加载必须显式决定：只在 Prefix 中记录异常并返回，可能仍让原方法加载当前文件。调用保存方法正常返回同样不证明写入完成，检查点应使用可核对的提交结果。

## 读取与迁移

1. 解析到临时普通数据结构，校验版本、必需字段、引用、数值范围与身份，再触碰运行对象。
2. 当前键优先；旧键仅接受明确白名单。多个有效候选冲突时拒绝猜测合并，保留定位信息。
3. 迁移为可重放的明确版本步骤。新数据验证成功再替换旧数据，记录迁移结果；不要先删旧记录再尝试转化。
4. 缺记录、未知版本、身份失配、损坏和合法空数据分别处理。不能让一个 catch 返回空对象把它们全部变成新局。

日号、现金和数量可以作为一致性辅助指纹，不能代替稳定身份；相同指纹可碰撞，外部改值也会造成误拒绝。对于可重建统计，可按明确规则重建并标为历史不完整。订单、奖励、剧情、库存和解锁等权威进度不得静默清空；保留原记录并暂停相关写入。

## 跨回调进度

将待交付、已交付、已保存回执分开；成功标记应有可以核对的结果。每次重试只处理已确认未完成的余量。读档期间暂停归因/计数时覆盖异常退出，避免把读档差额记成收入或消耗。

动态容器、机器槽和图节点如由宿主按位置保存，不能在不迁移的情况下改变结构或顺序。界面排序与业务存档身份分开；需要保存选中项时写稳定ID而非排序下标。

验证选择新局、正常保存重载、旧档迁移、回档、另存新槽、坏数据和部分交付恢复。格式检查和序列化成功都不等于游戏存档往返已通过。
