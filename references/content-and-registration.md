# 内容设计与注册

适用于物品、开局、Perk、角色、事件、掉落、机器/配方和生产系统。先核对原生经营循环、现有内容与当前公开能力，确定首版边界、获得/消耗途径、经济规则和失败路径；不因参考作品增加无关系统。

## 数据与行为分工

项目支持内容包时，把稳定定义与运行规则分开：物品、配方、角色、日程是声明；注册/应用、工厂创建、触发与结算是行为。纯资源包仍需核对宿主发现路径、清单版本、依赖、ID和脚本触发，不能只凭文件存在认定生效。

稳定ID使用本Mod的命名空间，显示名称和本地化可改变；不要把列表下标、包文件名或翻译文本作为跨版本身份。内容间引用需在正确目录就绪后解析，冲突时明确拒绝、覆盖或兼容策略，避免默认后加载覆盖。

## 注册分期

分别核对声明已接收、依赖已解析、目录已应用、工厂可创建、玩法已开放。提交返回成功只证明该阶段接受，不能等同所有内容已落地。整包验证原子性也不自动扩展到目录修改、生成物交付或游戏保存。

多项内容相互依赖时先做只读验证和顺序计划，再应用。个别条目失败是整组停用还是跳过该项，应按玩法一致性决定并报告。必需内容没落地时关闭相关玩法，不能继续展示可点击的空入口。

接入 Forge 时用实际安装版本的公共注册、能力状态和生命周期契约。框架提供公共能力，内容侧保留具体配方、资源与玩法；需要框架改造时按框架仓库约定另行处理。第三方包随附同一框架的多个版本时，先确认实际生效的一份，不能将调用者都算独立实现。

## 按内容类型补齐链条

| 内容 | 必须连接的行为 |
| --- | --- |
| Perk/开局 | 定义、选择/互斥、图标、本地化、实际生效；一次性初始奖励与普通读档分开 |
| 新物品/容器 | 目录与工厂、获得途径、形状/标签/资源/价值、用途、保存；复制模板不共享可变状态 |
| 角色/访客/商店 | 稳定角色ID、创建/肖像、库存、日程条件、事件触发、再次到访和读档 |
| 掉落/奖励 | 权重语义、过滤前后分母、无候选、数量边界；不要把权重当百分比 |
| 模块/节点/升级 | 准入、相邻或槽位规则、收益计算、材料/支付、成功副作用、已有物品迁移 |
| 工坊/解锁/剧情 | 前置条件、推进入口、一次性领奖、重复事件、保存回退，避免只改UI状态 |
| 日事件/委托 | 触发阶段、唯一事件键、生成上限、期限/完成/奖励顺序、跨天与读档去重 |
| 机器/配方 | 投料准入、选择、材料/工具区别、消耗、产出、余量、UI刷新与自动化入口 |
| 养殖/活体 | 成长时钟、饲料/水质/过滤/繁殖/收获的顺序、上限及保存；别把场景重开当时间推进 |

这张表是按需求选读的覆盖提示，不要求小补丁强行涉及所有系统。涉及库存/支付时组合 [库存与事务](inventory-and-transactions.md)，涉及跨日/一次性进度时组合 [状态与存档](state-and-saves.md)。

## 数值与生产

每个数值明确权威来源、单位、边界与计算阶段。真实条件、伪装/鉴定、用途类别、基础价值、生产加成、纯度与成交价分别处理；Tooltip仅负责展示结果，不能充当效果依据。

配方浏览可排序，但保存选择应按稳定配方ID。排序变化、材料变化后重新解析所选项；产出生成和材料消耗完成后才记成功。自动化投料与手动界面使用一致的资格规则，输出槽不能因错误锁定导致成品无法取出。

同一产物有多种配方时，产物ID不足以标识配方。使用独立配方ID或明确的稳定复合键；删除配方后显式清理/回退选中状态，不能悄悄让旧序号指向另一条。

验证按本次变化选择：重复注册、必需资源缺失、冲突ID、目录晚就绪、新建与旧物品、手动与自动化一致性、部分产出及保存重载。缺运行证据时只描述设计或静态链条已核对。
