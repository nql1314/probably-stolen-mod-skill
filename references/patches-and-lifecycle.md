# 补丁、依赖与生命周期

适用于规则调整、可选扩展、故障恢复和多补丁功能。先确认当前构建的完整签名及调用时机；接口缺失与对象尚未就绪是两种故障。

## 选择接入点

1. 优先已有公共注册、事件、目录工厂和原生操作入口；只补足实际缺少的行为。
2. 只改结果时，评估 Postfix 修改返回值或参数能否覆盖需求。Prefix 返回 false 接管原方法前，列清资格检查、状态变更、通知、存档标记与错误处理，确认哪些仍必须执行。
3. 目标包含声明类型、重载、参数与返回类型。反射按完整形状匹配；只看方法名、参数数目或类型名不足以确认契约。先做只读解析，再安装补丁。
4. IL2CPP 包装层存在成员不保证目标有可补的方法体。核对实际派生类型、入口与加载方式；构建不符时停用相关能力。原生地址/偏移必须隔离并按构建门控，不能用旧数值尝试写入。

## 安装与降级的边界

按功能定义必需钩子集合和可选钩子。必需集合不齐时保持功能惰性；可安全撤销时只撤销自身已安装的对应补丁。不要将捕获 PatchAll 异常等同于原子安装，也不要假定没有手工 PatchAll 就一定没装补丁；核对加载器行为和实际补丁所有者。

可选依赖分开检查“是否存在、版本是否适配、所需能力是否可调用”。不以目录里有某个文件代替已加载能力。依赖可能晚就绪时可等事件或有限重试；形状不匹配、损坏数据和不支持版本应直接关闭该能力并给出原因。

早期初始化只做安全配置、探测和暂存注册。目录、玩家和界面分别等其就绪时机；避免为了提前安装而触发原生类型的静态初始化。初始化已破坏原生类型时，异常处理不得再次访问该类型强行恢复。

## 嵌套调用与临时状态

只有一个同步动作时局部变量就足够。需要跨 Prefix/Postfix 保留状态时，用调用级状态令牌：记录是否进入、进入前深度、所属实例和本次需要恢复的值。嵌套调用用栈或深度，避免单全局 bool 被内层覆盖。

正常退出和异常退出共用一次释放规则；Postfix 与 Finalizer 都可能到达时，令牌须明确消费，防止双重恢复。释放关键状态不能依赖可能抛错的统计、日志或UI动作；将关键清理放进 finally，并保留原异常的传播语义。仅添加 Finalizer 不等于整条链已经异常安全。

同步调用返回后发生的异步任务或次日回调，要显式携带业务身份；不能继续借用已经退出的上下文栈。读档期间暂停统计时，也要覆盖加载失败后的计数恢复。

## 幂等与恢复

区分未尝试、执行中、已确认完成和结果不明。发放、注册、输入恢复等操作不能在可能失败的动作之前永久提交“已完成”。动作后应读取能够证明完成的状态；部分成功保留余量或补偿信息。

只有确认本次没有变更，或原操作有可靠幂等契约，才安全重试。结果不明时先对账；延迟重试、重复写入和吞异常都不能替代正确性。

| 状态寿命 | 应在何时失效 |
| --- | --- |
| 进程注册、静态能力探测 | 卸载或确有支持的依赖变更 |
| 原生对象、窗口、实例缓存 | 销毁、替换、场景切换；不要仅凭旧指针认身份 |
| 周目进度、待交付记录 | 新局、正常读档、回档、另存分别恢复 |
| 当日排程、临时统计 | 按明确的日边界刷新，读档不自动算新一天 |
| 一次交互的重入/去重令牌 | 本次操作结束或明确取消；不能按帧号永久去重 |

验证选择对应的成功、重复回调、嵌套、原方法异常、后置异常与实例替换路径。静态检查只确认控制流；实际安装及运行仍按本次授权另行验证。
