# UI、输入与刷新

适用于监控窗、库存装饰、列表注入、提示框和热键。先区分界面显示与权威业务操作；缓存的预览结果不能直接作为交易或升级的提交依据。

## 注入与对象所有权

等目标窗口和层级就绪后注入。以当前窗口实例与本 Mod 的稳定标记查重；同名节点不一定属于自己。多窗口不要共用一个“已创建”全局标记。关闭可保留可复用对象，销毁/换场景则注销引用，重新打开时按当前实例重建。

图标装饰可作为源 Image 的子物体，使用独立拥有者记录；只读装饰关闭 raycastTarget，避免吞掉原控件输入。按实际需求同步 sprite、材质、尺寸、遮罩和缩放，只在值变化时写入。多一个 Graphic 会增加处理量，是否增加 DrawCall 取决于材质、Canvas和批处理，需测量。

多个功能需要在同一区域呈现时，优先明确共享槽位/状态协议。私有子物体名、热键和固定坐标是脆弱约定；不能据名字存在就推定双方版本兼容。

## 刷新调度

先利用库存变更、选择变更、窗口打开和数值变化事件。将同一脏对象合并入队；只有缺少可靠事件或需要纠正漏事件时才增加巡检。

大量可延迟展示可采用“脏队列 + 轮转巡检”，同时限制单帧步数与软截止时间：

1. 为两类工作留出配额，防止持续脏事件让巡检永久饥饿；按对象去重，失效对象及时移除。
2. 预算覆盖队列准备、索引重建、快照和清理。一次 ToArray 或全量入队本身也可能成为尖峰。
3. 在单项之间检查截止时间只能提供软预算；某次单项调用仍可能超时。大遍历或搜索需要限制单项规模或保存游标分步执行。
4. 关键交互可触发立即刷新；后台展示允许延迟时写清可接受范围。扫描周期不等于最大响应延迟，还取决于积压、配额和单项耗时。

缓存键包含实际依赖：物品/库存实例、状态版本、语言、筛选或选中项。价格、数量、条件变化后使相关缓存失效。UI排序和筛选变化时按稳定业务ID保留选中项，不能保存列表下标当业务身份。

## 输入与关闭路径

一次性热键按按下沿触发，只在游戏窗口有焦点、目标玩法可用、文本框或输入法未接管时生效。改键捕获流程与普通热键分开，避免捕获同一键后又触发动作。重绑定要校验组合键、保留值和冲突。

Unity 托管引用可能在原生对象销毁后仍存在。组件访问前用 Unity 空值语义检查，不能靠 `?.` 保证有效。覆盖层只接管自身需要的输入范围；拦截全局 Input 或 EventSystem 会影响原版UI及其它扩展，采用前必须确认自己的界面也不依赖被拦链路。

关闭按钮、同一热键切换、场景切换、卸载与构建失败应汇到同一清理入口，释放焦点、IME、鼠标捕获、hover和拖拽状态。需要等待按键松开时只作用于这次交互；窗口已关但守卫未解除不能算关闭完成。

看门狗只在能区分合法输入与卡态、且有可靠恢复入口时考虑。鼠标未按住不自动证明拖拽无效；帧数阈值随帧率变化，也不能替代输入来源和焦点判定。

验证按涉及范围选择：重复开关、多实例、场景切换、改键/中文输入、遮罩/缩放、持续脏事件、大仓库及缓存失效。性能声明需要对应场景测量，预算常量本身不是优化结果。
