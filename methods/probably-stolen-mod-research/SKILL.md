# Mod 实现研究与知识入库

目标是解释实现怎样工作、在哪些条件下值得复用，以及如何帮助后续优化。覆盖所有研究对象，不等于每个对象都必须贡献一个“优秀模式”。简单替换、纯资源包、重复依赖和没有可复用结论的对象也要得到准确记录。

## 范围与执行入口

默认研究输入：`D:\workzone\probably-stolen\mods`。默认知识库：`D:\workzone\probably-stolen-mod-skill`。路径可以由用户替换。

- 本 Skill 是研究方法；知识库根目录 `SKILL.md` 和 `scenarios/` 是后续开发使用的成品。
- 原始事实、Mod 身份、证据和评审保存在 `<知识库>/packages/mod-research/<批次名>/`。该仓库目前忽略 `packages/`，它是本地研究档案，Git 提交不会携带它。跨机器交接时需显式交付研究目录；无需复制整套二进制，只传所需证据并列出缺失原件。
- 开始时读取适用的工作区指令、Git 状态和本次阶段的输入。保留现有修改、删除和用户文案，不凭历史记录恢复文件。
- 用户只要求设计方法时，只维护方法文档。用户指定阶段或对象时，只执行对应工作。只说“执行研究”而未限定阶段时，先完成 A 阶段并交付任务清单；不默认启动所有模型或进入入库阶段。
- 研究默认静态、只读地检查输入；不执行收集来的 DLL、安装器或构建脚本，不启动游戏，不修改 Mod 实现。需要二进制检查时使用当前环境可用的逆向工具和相应技能；工具缺失、混淆或无法解析时交付已知事实和阻塞点，不猜测内部实现。
- 本方法不固定模型品牌、型号或推理档位。由用户选择执行模型；分阶段文档可由不同模型在不同会话完成。不自动创建聊天、安排后台任务或派发子代理。

## 阶段与职责

| 阶段 | 建议承担者 | 输入与交付 | 阶段边界 |
| --- | --- | --- | --- |
| A 盘点与试点安排 | 低成本模型；用户可自行协调 | 输入快照、包与分析单元映射、分析任务单 | 确认范围和重复关系，不评价实现优劣 |
| B 单 Mod 分析 | 低成本模型 | 每单元一份实现报告、证据片段和待核实项 | 事实与推断分开，候选模式不能直接升级为规则 |
| C 比较与复核 | 高能力模型 | 主题比较、模式卡、退回问题、优化候选清单 | 核查原始证据，保留反例和适用边界 |
| D 知识入库 | 高能力模型 | 对开发 Skill 的最小改动及内部映射 | 只写本轮已审结论；不修改 Mod |
| E 覆盖与交接 | 当前协调模型 | 覆盖统计、未决项、下一任务 | 区分已处理、分析完成、复核完成与入库完成 |

首次批量运行建议先选 3–5 个不同类型的对象完成 B，再由 C 复核模板是否能保留关键证据。根据实际缺口调整方法后继续全量；样本试点不能替代剩余对象。框架、复杂状态/存档、简单规则和资源内容可作为选样方向，目录分类不代表真实架构。

## 按阶段读取

- A 或 E：读 [盘点、分批与覆盖](references/inventory.md)。
- B：读 [分析步骤与报告模板](references/analysis.md)，只接收分配的对象和必要依赖。

## 证据与结论的共同规则

1. 每个实现事实定位到本次输入中的具体文件、类型/函数/配置键和证据编号。README、名称、评论和旧报告只能提供检索线索，不能替代实现证据。
2. 标明来源性质：直接实现证据、现有运行记录、文档声明、分析推断、未知。另列实际验证阶段：静态、编译、加载、行为、保存重载；后者不是可以自动递进的分数。
3. 源项目比发布包更新时，只能证明该源项目版本；不能把开发分支中的修复说成发布 DLL 已具备。框架内部实现也不能记为每个使用它的 Mod 自行实现。
4. “发现模式”“值得复用”“适用于当前环境”“已经实测”分别给出依据。单个案例可以贡献有边界的经验；多个案例共享同一段实现时不能作为多个独立佐证。
5. 性能、稳定性、安全性和兼容性结论与证据强度匹配。没有测量就描述复杂度、分配点、扫描频率及可能影响，不宣称提升比例或必然无冲突。
6. 成品开发指南按场景组织，写选择条件、实现步骤、代价、失效边界和验证办法。真实 Mod 名称、原始包名、本机材料路径及调查过程留在研究档案；成品不能依赖未随附的研究材料才能使用。
7. 检查与当前文档任务相称：检查引用、证据链、覆盖账和 Skill 格式，不构建全部 Mod，不执行原生测试，不制作无必要的备份或哈希清单。

## 完成判定

单次会话完成所分配阶段后即可交付，不为了“全量完成”跨越用户给定范围。报告精确的完成对象、输出文件、未决项和下一阶段输入。

全批次只有在快照内所有包均已归类、所有唯一分析单元的必需范围均有结论、复核问题已经处理、采纳规则已入库或明确不采纳时，才能称为本批次研究完成。无法分析的对象保留阻塞或有限覆盖，不把它们算成完整分析；素材包无代码不构成阻塞，应研究其加载契约和资源组织。
