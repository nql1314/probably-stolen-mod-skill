# 场景：开局 Perk、点数、图标与效果

适用：新增可选 Perk、改变选择点数/数量，或把已选 Perk 接入开局、每天和具体玩法。游戏方法名是候选入口，先在当前构建核对声明类型和完整签名。

## 先区分两种需求

| 需求 | 接入点 | 完成条件 |
| --- | --- | --- |
| 增加选择点数或可选数量 | `PerkUIController.OpenUI`、`OnChange`、`SelectPerk` 的实际重算路径 | 打开界面、选择和取消后，显示值与可选限制一致；配置确实参与计算 |
| 新增一个 Perk | `StartingPerkList.InitStartingPerk` 后注册，选择界面显示，`HandleNewGamePerk`/日更/专属玩法钩子派发效果 | 列表、图标、说明、消耗、互斥、存档选择和效果全部成立 |

## 新 Perk 的最小路径

1. 为 Perk 设稳定且带命名空间的 ID、点数消耗、显示名/说明键、互斥 ID。查当前构建的 Perk 模型；从游戏提供的工厂创建，或复制兼容模板后建立独立实例。注册前按 ID 查重，冲突时停用该条并记录原因。
2. 在 Perk 目录初始化完成后追加到游戏列表。选择 UI 可能从另一份列表或预制件生成，需要在 `PerkUIController.OpenUI` 等实际入口补齐显示；每次打开先检查已有元素，避免重复克隆。
3. 图标按 [图像示例](sprites-and-icons.md) 加载并缓存。核对 Perk 图标字典何时初始化；若加载顺序靠后，在 `StartingPerkIconLoader.Start` 一类入口补登记。缺资源时使用明确的占位图或禁用该 Perk，不能留下空引用。
4. 效果只在选中该 ID 时执行。使用游戏已保存的已选 Perk 集合作为权威状态，不用 UI 是否曾点亮作存档依据。开新局效果通过 `StartingPerkContent.HandleNewGamePerk` 一类入口；每日效果通过 `PlayerStore.BeginDay`/`EndDay` 一类入口；专属玩法效果在对应判定或交易入口实施。
5. 一次性发放以“存档槽 + 周目 + Perk ID”或当前游戏提供的等效稳定身份去重。目标库存未就绪、奖励未落地时保留重试机会；写后核对实际数量/状态。

## 效果类型选择

| 类型 | 建议实现 | 特别检查 |
| --- | --- | --- |
| 开局一次性物品/资金 | 新局回调里确认选中、确认落点后发放 | 读档不能再发；目标不可用时可重试 |
| 永久数值/资格 | 在消费该值的原生方法里按已选状态调整 | 游戏重算时仍生效；不污染未选周目 |
| 事件触发奖励 | 在事件完成后的回调追加，使用事件身份去重 | 概率范围、奖励接受结果与重复回调 |
| 每日或夜间效果 | 在实际日界/夜结入口执行，记录游戏日 | 读档回放和同日多次调用 |
| 互斥/组合 | 用稳定 ID 建立双向关系，并核对 UI 与保存校验 | 缺失的第三方 Perk ID 不应导致整个列表失效 |

## 点数与数量

检查 UI 控制器是否在 `OpenUI`、`OnChange` 或 `SelectPerk` 重写上限；在最后一次原生重算后施加配置值。点数与数量分别验证，保留合法配置而非启动时强制常数。若改变选择规则，需要查原方法是否同时处理消耗、互斥和按钮状态，不能只改标签文字。

## 验证

新局选择、互斥/点数边界、图标显示、效果触发、读档、再开新局各走一次；日志分别确认补丁安装、注册数量和实际效果。没有运行证据时只报告静态实现。
