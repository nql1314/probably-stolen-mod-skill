# 场景：导入图像、创建图标、替换 Sprite

适用：给新物品或 Perk 配图、为角色注册肖像、替换现有物品外观，或向 UI 提供图标。这里处理资源与 Sprite；图标插入现有界面还需读 [界面注入示例](ui-injection.md)。

## 资源路径

1. 确定图像归属：随程序集嵌入、随内容包声明，或放在约定的用户资源目录。运行时记录预期路径/资源名；缺失时给出可定位的日志和回退。
2. 校验 PNG/JPG 解码、最大文件体积与尺寸。按目标用途创建 `Texture2D` 与 `Sprite`，使用当前 Unity 构建适配的加载 API；像素/锚点、裁切、透明通道按目标游戏同类素材核对。
3. 以“资源 ID + 变体”缓存 Sprite。不要在 `OnGUI`、物品每次渲染或 tooltip 刷新中反复解码/创建；场景销毁或热重载时处理 Unity 资源与引用寿命。
4. 将 Sprite 接到正确的解析路径：物品目录或 `GameItem.SetSprite`、Perk 图标表、角色肖像字典、UI `Image`。如果显示元素在加载后被游戏 `Validate` 重建，应在其就绪/重建点重新绑定，而不是无限每帧覆盖。

## 选择更新方式

| 目标 | 操作重点 |
| --- | --- |
| 新物品图标 | 注册物品 ID 后绑定图像；背包、商店、地面/展示柜逐处检查 |
| 开局 Perk 图标 | Perk 注册和图标加载的先后顺序；缺图标占位 |
| 角色肖像 | 用稳定角色 ID 对应肖像键；加载前先验证图像；客户创建/追踪与 Sprite 查找都可能使用肖像 |
| 物品颜色或主题 | 原图和颜色变体分别缓存；用物品自己的标签保存选择；未知变体回退游戏原图 |
| 用户提供的图片 | 限制扫描深度、候选数、文件体积和分辨率；配置路径失效时回退内置图 |

## 验证

核对资源确实包含在发布产物中；检查透明度、比例和清晰度；打开/关闭 UI、切换场景与读档后重看图像；日志确认没有重复创建或资源泄漏。静态存在 PNG 不能证明目标构建的 Sprite 解析器已取到它。
