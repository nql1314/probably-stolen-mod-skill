# 场景：绘制独立游戏内 UI

适用：监控面板、工具窗口、调试列表和不必嵌入原有界面的操作页。先确认需求是只读信息还是会改动游戏状态；写操作需另用对应的交易/库存示例核对。

## 轻量显示路径

1. 在 `OnUpdate` 里检测热键按下沿、游戏窗口焦点和相关玩法状态。面板可见且玩家/场景就绪时，按数据变化事件刷新；无事件时用有上限的节流轮询。
2. 在 `OnGUI` 中只绘制已经准备好的快照、窗口位置和按钮。不要在绘制回调里扫描所有库存、反射查方法、解码图片或写存档。
3. 将窗口位置、尺寸、行数、显示状态放入有边界的偏好设置。屏幕尺寸变化时把窗口约束到可见范围。
4. 读档、新局、切场景时清掉旧的玩家、机器和 UI 引用。读取 `PlayerStore` 等实例前确认已加载；若游戏正在反序列化或执行结算，延后读取。

## 需要原生风格时

在游戏窗口层级就绪后创建 Unity UI 对象，按现有面板的层级、字体、布局、输入事件和关闭流程挂载；需插入现有界面则读 [界面注入示例](ui-injection.md)。覆盖层只在自己的输入区域或模态状态接管输入，不能让普通 gameplay 热键整体失效。

若覆盖层打开时原版 tooltip 或射线检测持续报错，先用堆栈和实际帧调用确认出错对象与入口，再选能覆盖该路径的局部修复。补丁显示“已安装”仍要在同一操作下复核错误是否消失；不能仅凭安装日志扩大屏蔽范围或宣称修复。

## 会改变玩法的调试动作

按钮调用对应的原生工厂、规则和交易路径，执行前确认当前周目、玩家/商店实例与目标库存，执行后核对真实结果。需要正品或特定品质的物品，读取原生真实条件；成功提示不代替实际接纳与数量读回，见 [库存](inventory-and-trade.md)。

“下一位访客”一类一次性覆盖，用与当前周目关联的互斥待处理意图，在真正替换队列条目时消费一次；点击只设置意图，不能提前改错队列。取消、失败、读档、新局或返回主菜单时按需求清理，避免旧意图流入下一周目。用户明确删除的调试操作同时移除按钮、热键、配置和执行路径，不保留隐藏入口。

## 验证

开关面板、移动/缩放、分辨率变化、读档和场景切换后检查数值与引用；面板隐藏时确认无昂贵轮询。若仅静态分析，注明布局和输入行为尚未在游戏里确认。
