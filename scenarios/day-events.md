# 场景：每日事件、日历、委托和进度

适用：跨天更新、定期角色到访、日历标记、随机事件、委托前置链和一次性奖励。

## 选事件边界

查当前构建中 `PlayerStore.BeginDay`、`EndDay`、`EndNight`、商店开关门、`StoreEventManager.ActivateEvent`、客户入队和委托完成的顺序。选离业务结果最近的回调；不要仅因一个方法名带有 Day 就假定它每游戏日只调用一次。原版事件若已有注册或队列 API，先使用它。

## 日程与标记

安排未来访客前检查解锁条件、日期语义和队列中是否已有同 ID 同日角色。日历标记从权威排期或已确认的观测记录重建，用自己的 ID 前缀识别和清除；只清理本功能生成的标记。UI 打开后再刷新显示，避免在日历对象未就绪时写入。

## 委托/事件链

用显式的前置 ID 列表描述关系，不从 ID 后缀推断顺序。抽取前统一检查每日容量、唯一状态、声望/解锁和已完成前置；抽中后存入游戏支持的请求列表。完成回调写进度并交付奖励时，按请求身份去重且复核奖励落点。到期/取消与滚回旧存档的状态要有明确处理。

## 状态寿命

区分进程内冷却、单日次数、周目唯一完成与跨存档共享设置。与周目有关的记录使用 [存档示例](save-state.md)；不把周目状态写进全局 MelonPreferences。随机概率明确范围及在失败后是否消耗一次机会。

## 验证

连续两天、同一天读档、事件触发前后读档、队列已存在、前置未达成、奖励库存满；检查日历与实际到访/委托状态一致，无重复奖励。
