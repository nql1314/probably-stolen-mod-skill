# 场景：拖放触发的升级与物品交互

适用：把材料拖到工具/机器上升级，拖入容器交换物品，或在 UI 拖放结束后触发一次操作。库存转移和交易还需读 [库存与交易示例](inventory-and-trade.md)。

## 判定顺序

1. 查清当前构建中 `ItemMouseDragHandler.EndDrag`、`ItemMultiSelectHandler.EndGroupDrag`、目标物品的 `Can...Target`/`On...Target` 等实际调用顺序。两种拖动入口可能属于不同类型；核对完整签名和可见性。若游戏先处理自己的拖动，等其状态稳定后再识别最终源和目标；不要在多个回调里各执行一次写入。
2. 在**只读阶段**判定源物品、目标物品、所有权、数量、升级等级/上限、修饰键和目标命中区域。缺任何条件就交回原逻辑或明确拒绝，不扣材料。
3. 为同次拖动建立临时操作令牌；同一松手、组拖或重入回调只能进入一个写路径。UI 关闭、切场景、失败时释放令牌。
4. 提交前再次核对材料数量与目标状态，并记录可恢复的旧值。优先使用游戏已有的原子操作；否则先确定材料预留/消耗和目标写入各自的失败补偿，再按当前 API 可安全执行的顺序提交。每一步都读回实际结果；两者都成立才报告成功。若任一步失败，执行并验证回滚；回滚不完整时保留可追踪的待补偿状态，禁止重复扣料或免费升级。无法可靠补偿时拒绝这次操作。
5. 将物品独有等级/效果写入隔离的可保存标签，设置默认值和旧格式迁移；tooltip 从实际标签读取，而非只显示配置步长。

## 配方表形状

将“目标类型 + 材料 ID → 升级属性、步长、上限、消耗量”放在数据表中。每个条目校验 ID 与数值范围；特例放在命名清楚的独立分支。上限满、材料错配、非玩家所有或空槽都不应消耗物品。

## 复杂物品交互

锁、液体、槽交换等操作优先调用游戏的验证/执行辅助方法。液体明确使用毫升或升并在读回时核对实际转移量；需要暂时移出物品才能操作的流程，把“归还原位置或可追踪替代位置”放进失败路径。

## 验证

单拖、组拖、失败拖放、重复回调、满级、读档后升级各测一次；另检查材料消耗失败、目标写入失败及补偿失败的路径。核对材料数、目标标签、tooltip、库存位置与日志。只看动画或文本提示不能确认升级已保存。
