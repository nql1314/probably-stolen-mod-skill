# 场景：设置、数据文件与本地化

适用：可调数值、热键、目录型内容数据、多语言名称/说明。设置只有进入实际行为计算或 UI 路径才算生效。

## 内置数值与覆盖顺序

先确认改的是编译内置默认值、运行时设置还是已保存的周目规则。项目已有 `BuildConfig` 时，在所属数值表修改内置价格、材料数、属性步长和上限；声明、实际计算、领域检查与说明读取同一来源。框架数值由 Forge 持有，玩法数值由内容 Mod 持有。一次默认值调整不自动新增设置菜单、偏好条目或外部 JSON。

沿实际读取路径检查“内置默认值 → 有效运行时配置 → 周目快照”的覆盖关系；不同项目以自己的契约为准。旧 JSON、MelonPreferences 或存档中的 `ConfigSnapshot` 可能继续覆盖新默认值，重编译不保证旧周目数值改变。需要验证默认值时使用未被覆盖的配置和新周目；已有周目的迁移只在需求涉及迁移时执行。

单位明确区分整数百分点、基点、信用点、件数、格数和液体体积。稳定 ID、存档版本、原生枚举和必要算法边界不能为了“集中所有数字”变成玩法配置。占格改变时同步原生形状、图像导出与显示；文案从真实规则生成。

## MelonPreferences

为设置提供安全默认值与有效范围；读取后将概率、倍率、尺寸、周期和数量分别校验。分类名应与插件实际注册及管理界面的匹配规则一致。旧键迁移应保留用户已有合法值，迁移成功后再写新键；若旧分类已无有效值且可以安全重建，优先让新分类重新初始化。热键要排除游戏窗口失焦和不相关界面，动作型热键用按下沿。

日志等级区分构建默认值与已有用户偏好；本地开发沿用项目默认 `INFO` 或其明确覆盖，探针显式用 `DEBUG`。保留 `MelonPreferences.cfg` 中有效设置，不用清空偏好文件的方式让日志开关生效，见 [构建与排查](build-and-verification.md)。

## 自定义数据文件

解析前确定格式版本、编码、允许的字段及最大文件/条目数。逐条校验稳定 ID、引用 ID、数值范围、必填资源与重复项；错误日志包含文件及条目位置。需要整份配置一致时，先完成全量校验再发布，失败则保留用户原文件并使用明确的默认配置，不把前半部分有效数据当成完整内容。跨文件引用需要统一验证后再注册。

## 本地化

优先沿用游戏或项目现成的本地化键路径。为目标支持的每种语言分别提供新增物品、效果、Perk、角色、按钮及所属 Mod 显示名称；不要把“中文 / English”拼成一条文字。缺键时按游戏既有规则显示可读回退，不显示内部 ID；交付前补齐目标语言的缺键，避免正常语言选择下出现中英混排。

动态 Tooltip 使用实际状态和单位生成。物品字段、效果定义或界面缓存若保存了已翻译文字，应在语言切换和内容刷新时重新取值；读档物品也要更新显示，不能永久沿用创建时的语言。分别检查新建与读档物品的名称、效果和来源行，确认与当前游戏语言一致。

## 验证

默认配置、合法自定义值、越界值、旧配置迁移、缺失资源、不同语言各检查一次；日志能定位无效项。内置数值变更再检查无覆盖的新周目与已有快照分别采用什么值。按本次测试范围确认实际结果变化，不能只看到设置面板或编译常数变了。
