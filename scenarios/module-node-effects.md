# 场景：模块、节点与效果

适用：新增可安装模块或节点、效果槽、邻接/摆放效果、临时属性重算、机器工作成长与衰减。物品、效果定义和实际回调是不同能力；还需读 [物品](custom-items.md)、[图像](sprites-and-icons.md) 和 [存档](save-state.md) 中与需求有关的部分。

## 定义与注册

分别维护稳定的物品 ID 与效果 ID。只需要附着在模块上的效果时，不要额外注册一件同名物品。核对目标目录、`MODULE`/`NODE` 类型、机器准入、真实占格、基础属性、效果槽数和随机池资格；从同类型模板创建独立实例，并清除不应继承的随机效果或可变状态。

向原生随机效果入口交出实例后，按该入口允许的结果验证每个效果槽的 ID、类型和上限。不要假定第二槽必为空，也不要为了满足本方工厂检查而重抽已经生成的原生结果。旧存档物品是否迁移或重抽应另行决定。

声明提交后，逐项检查目录应用结果和实际创建实例；整组提交只覆盖声明冲突，不能代替目录工厂的结果。依赖原生效果类型的补丁等目录就绪后再安装，失败时停用该效果回调，避免在异常处理里再次触发已故障类型的初始化。

## 属性与工作回调

把可保存的基础属性、每次重算生成的临时属性、成长记录分开。邻接计算以当前占格 mask、方向和实际连接关系为准；多个来源的优先级、互斥、取整和上限应有确定规则。先确定原版临时属性重算的前后顺序，再应用隔离、转换或增益；重复重算不能把上次的临时结果再次累加为输入。

机器动作通知可能发生在无电、缺料或输出被拒绝的路径。成长或一次性效果应以目标机器的成功生产证据为门槛，并按机器实例及一次工作身份去重；仅检查收到动作回调不足以认定成功。持久成长记录与物品实例绑定，读档后核对属性；每日衰减按实际未工作的游戏日处理，不以进程时间推断。

## 验证

先用纯规则检查几何、排序、取整和重复调用，再在游戏中分别确认注册、实例生成、效果槽、邻接和旋转、重算、成功工作、无电/缺料/满输出、保存冷启动回读。编译、目录 `Applied` 和补丁安装各只证明所在阶段，不能推导出最终属性或机器效果。
