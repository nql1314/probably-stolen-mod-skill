# 场景：Nico 工坊进度链与领奖

适用：给内容 Mod 添加独立工坊标签、前置图、成就、资源解锁或一次性奖励。先读 [Forge 接入](forge-integration.md)；原生网络升级和商店服务使用 [商店进度](shop-progression.md)。

## 声明展示与关系

通过当前 `ForgeWorkshopApi.RegisterChain` 注册 owner、稳定链 ID、本地化标题、快照提供者和操作回调。属于不同内容方的进度保持独立，不靠覆盖框架已有页面来插入自己的节点。

快照从当前周目与实际资源构建，玩家或存档未就绪时允许暂不可用；不长期持有旧玩家或库存句柄。核对条目 ID、分组数量、条件与奖励引用以及图坐标。文字和按钮状态由同一份已校验状态生成。

| 字段或关系 | 含义与检查 |
| --- | --- |
| `Dependencies` | 真正的解锁前置；引用有效，无自引用或循环，执行时再次检查 |
| `VisualLinks` | 主题连线；不能被当作购买或领奖前置 |
| `Conditions` / `Rewards` | 展示要求与奖励；`Consume` 不会替内容方扣料，奖励声明也不会自动发奖 |
| `Completed` | 成就条件已达成；与已经领取或解锁分别记录 |
| `Unlocked` / `ActionEnabled` | 已领取或解锁状态与当前操作资格；与持久进度一致 |

## 执行解锁或领奖

1. 回调收到条目 ID 后，从当前存档槽、周目和条目状态重新核对资格、前置、余额、材料所有权与输出空间；UI 快照可能已经过期。
2. 用“槽位 + 周目 + 条目 ID”识别一次操作。重复点击、双击与重入只进入一个提交路径，已完成奖励不再发放。
3. 先确定扣款/扣料、状态变更、奖励交付和失败补偿的顺序；每步检查原生返回值与实际资源变化。奖励受库存容量限制时，完成预检或记录待交付余量。
4. 持久化结果并核对目标槽文件，再刷新展示。`Stage`、操作回调返回或“unlock invoked”日志均不能单独证明交易与保存完成；结果不明时先对账，见 [存档](save-state.md)。

达成条件、允许领取、已经交付和持久完成分开处理。失败时保留可恢复记录，禁止重复扣料、免费解锁或重复发奖。条件展示函数只读，不在快照刷新时推进进度或发放资源。

## 验证

离线检查图关系、条件边界、奖励规则和重复执行，再按本次测试范围检查页面显示、余额不足、材料不足、满库存、快速重复点击、切换存档与保存重载。同时核对现金、材料、奖励落点和进度；节点变色或按钮禁用不能证明交易闭环。
