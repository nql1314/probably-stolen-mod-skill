# 场景：添加自定义开局

适用：新增一套可选初始条件，包括起始物品、现金、租金、升级、声望或允许的开局类型。若只是选择一个开局 Perk，使用 [Perk 示例](starting-perks.md)。

## 定义与校验

用带命名空间的 ID 和格式版本描述开局；列出允许的原生开局类型、点数或费用、物品增删、状态增减及本地化文案。加载数据时校验 ID 唯一、数字范围、物品引用存在、互斥关系和配置版本。某一构建的枚举整数不能当成跨版本稳定 API。

若需新增原生开局类型、修改菜单资格或接入首次存档，先按构建标识和目标方法完整签名门控整条流程；在不匹配的构建中隐藏入口并停用写入。菜单显示、玩家点击和新局创建要由同一个短期意图关联，切换菜单、读档、新局失败或会话更换时使旧意图失效，避免孤立的开局状态流入普通周目。

## 应用时机

1. 在主菜单/开局选择列表就绪后显示选项，但此时不修改玩家状态。
2. 在游戏新局初始化完成、玩家与库存可用后应用开局内容。先核对当前存档槽与周目身份；若使用自定义菜单，再核对本次选择意图。记录尚未执行、部分完成、已完成三类状态；只在已实际放入物品/写入状态后标记完成。
3. 移除物品先核对所有权与数量；新增物品使用当前目录创建，并走游戏接受条件。现金、声望和升级调用当前构建的游戏方法，再读取结果确认。
4. 读档只恢复状态，不再次应用一次性开局内容；切换存档槽或新建周目时重置对应缓存。若依赖异步初始化，使用有限重试且避免一帧多次发放。

## 首次存档与失败恢复

若开局状态必须与游戏第一次保存一起写入，先确认原生保存窗口的顺序和可写扩展点。在写入前复核玩家/商店实例、周目 ID、槽位和现有状态；序列化前限制记录大小与条目数，保存后从目标槽回读并核对身份、版本与关键字段。写入扩展状态、分配槽位和游戏保存未必构成一个事务；任何一步失败，都要明确已创建的槽位与状态如何恢复或留待人工处理，不能把“已调用保存”当作完成。配置说明中的格式版本须与实际读写格式一致。

## 验证

新局选择后检查每项变化；库存不足、满格或引用缺失时检查部分完成和重试；保存重载与另一存档槽不重复发放。对新增原生开局，还要验证构建不匹配时入口关闭、首次保存失败后的槽位状态、保存回读和旧意图失效。若必须读取原生字段偏移，记录当前构建特征并单独做运行验证。
