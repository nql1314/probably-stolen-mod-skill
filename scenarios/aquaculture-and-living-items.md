# 场景：水产养殖与活体物品

适用：扩展循环水养殖系统、鱼类/鱼卵/鱼苗、饲料、过滤、收获，或其它依赖活体状态的经营玩法。Build `26017150` 的水产系统是本轮核对入口；具体方法、单位和规则仍按目标构建确认，不把普通机器模板视为完整养殖模拟。

## 先追踪原生状态与夜结

从当前构建的 `AquacultureItems` 及相关养殖辅助类型追踪工厂、槽位、喂食、夜结和加载。活鱼、鱼卵、鱼苗群、死鱼和加工产物可能是不同 ID/状态及不同工厂；显示成同一鱼种不代表具有同一生命周期。

先列出本次要读写的真实字段：物种、阶段、体重、年龄、健康、饥饿/热量储备、饲料来源、繁殖/蓄卵和累计手术结果。按实例持久化，不能按物品 ID 共用一份成长记录；未知阶段和缺失状态不能默认为成熟或满健康。

查清原生夜结中排污/净化、过滤、水量与生存、饥饿、成长、繁殖、发电和保存的实际顺序。扩展只接管需要改变的环节，保留原生其它环节；已经参加原生全物品枚举的库存图不再另调一次成长或夜结。

## 投料、容量与资源

| 对象 | 核对重点 |
| --- | --- |
| 养殖槽 | 网格扩建、真实储水容量、鱼的总需水量分别计算；增大格子不等于增加储水 |
| 饲料分配器 | 食物先进入可用储备，鱼再按条件摄食；投进鱼缸不等于已处理或已进食 |
| 饲料 | 肉食/杂食等适用条件、热量比例、成长与肉质效果；不同来源不能只按总卡路里合并 |
| 水与滤芯 | 实际液体组分、污染与滤材适用性、耐久、缺水；过滤不补水也不替代供电 |
| 电量 | 当前设备真实功耗与原生时序；电鳗等生产者的阶段/饥饿资格、相邻接收者与充电条件 |

Forge 液体声明通常以 ml 表示，底层 `1000 part = 1 ml`；以实际 API 单位为准。饮用水质量评分、装满百分比和养殖所需水量/污染浓度是不同指标；不能用其中一个代替另一个。供电与倒液的通用边界见 [机器](machines-and-recipes.md)、[库存](inventory-and-trade.md)。

## 成长、收获与经济

不能把所有物种都设计成可圈养繁殖，也不能只凭当前年龄保证成长：需水、健康、饥饿、饲料与混养捕食可能改变结果。阶段转换前后还要核对真实占格及剩余空间。

收获或手术先核对物种、阶段、真实可产量、工具、健康和输出空间，再执行原生动作。活体取卵与屠宰的产物规则不同；累计手术记录不能在恢复健康、读档或再次取卵时重置。刀具继续分割的产量按剩余实际资源计算，不能每次重新发整条鱼的产出。

经济设计计入投入、饲料、用水/过滤、电量、等待、死亡风险及销售资格，不只用成熟售价除以名义天数。新鱼肉、医疗材料、鱼卵等用途类别与真实价值按 [价值与条件](item-value-and-conditions.md) 接入。

## 验证

按改动选择正常养殖、投料未处理、缺电/缺水、无效滤材、成长换阶段、满槽、混养、收获失败与保存重载。读回实际活体字段、饲料、液体组成、能源和产物；界面健康条或年龄变化不能单独证明整次夜结正确。未执行游戏内测试时只报告接口/静态检查范围。
