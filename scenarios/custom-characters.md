# 场景：添加自定义角色或访客

适用：新顾客/商人、定期到访角色、角色肖像、携带库存、购买偏好和对话。换皮现有角色只需要身份/肖像路径；真正新增角色还要接入创建、排期和交易规则。

## 内容定义

为每个角色写稳定且带命名空间的 ID、模板类型、显示名/本地化键、肖像、解锁条件、到访日程、购买标签、预算或价格修正、库存条目及对话关联。若项目已用角色内容运行时，先按它的 schema 和 API 版本声明数据；若直接创建，核对当前构建的客户工厂、排期表及 `StoreClientManager` 相关方法。

## 已依赖 Forge 时

先读框架当前 `docs/CONVERSATION_API.md`，按用途选入口：`ForgeDialogueApi` 提供选择定义，`ForgeClientVisitApi` 预约剧情来访，`ForgePhoneApi` 接入联系人，`ForgeSupplierApi` 承载供货会面，`ForgeReadingApi` 提供阅读窗。剧情来访是只对话顾客，不自动获得商人库存或交易业务；阅读窗打开也不代表读完或剧情完成。

预览/货单捕获只读；提交回调按当前周目、会话和资源重新验资。来访/电话按其契约限制一次提交，供货继续页重新捕获货单并建立新门控，不能复用旧页回调反复扣款。原生菜单有容量限制，使用当前分页适配，不直接塞入任意数量的按钮或跳转图。

请求 `Queued`、`Arrived`、`Dismissed` 分别表示排队、出现和离场，不能代替业务完成。`Indeterminate` 时保留请求并对账，不自动重约。框架请求队列不替内容保存剧情进度；读档、主菜单和分槽后旧会话失效，由所属存档状态决定是否重新预约。图片复用 [公共资源路径](sprites-and-icons.md#资源路径)。

## 最小接入路径

1. 需要原生商人或自定义角色工厂时，在对应目录/内容系统就绪后注册；核对 ID 冲突和物品引用。使用 Forge 剧情来访时按其预约契约，不再重复注册同一客户工厂。肖像先解码并缓存，详见 [图像](sprites-and-icons.md)。
2. 在游戏提供的排期或客户队列入口安排访问。候选方法有 `TryAddClient`、`AddClient`、`QueueFuturClient`；需要确认每个方法的调用方、日期语义和同日重复规则。入队前用角色 ID + 游戏日查重。
3. 到访时从模板创建**独立实例**，设置实际购买偏好、预算、库存和肖像。动态库存要在合法目录中创建物品，并检查槽容量；不应只在 UI 上显示“有货”。
4. 对话与名字优先走游戏本地化/对话数据入口。若要随状态切换肖像，应只作用于该角色、该事件，并在角色离场时清理旧表情状态。
5. 读档时恢复排期/已到访状态；新局另行初始化，避免同一角色被多次插入队列。与进度解锁关联时继续读 [每日事件示例](day-events.md)。

## 验证

确认角色出现在正确日期、肖像与名字显示、交易偏好和库存实际生效；跨天、读档、同日重新进入场景后无重复角色。内容文件能解析，只证明意图，不能证明游戏已排期或可交易。
