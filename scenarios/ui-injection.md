# 场景：向现有界面插入图标、按钮和列表

适用：在 Perk 选择页、客户平板、物品窗口、日历等已有 UI 中补一个图标/按钮，或把列表改成可滚动区域。先确定目标是 Unity UI、游戏自有窗口，还是 IMGUI；不要把这三种层级混用。

## 找到正确时机

1. 在当前游戏构建查目标界面的创建、打开、刷新和关闭方法，以及对应父节点/预制件。候选入口包括 `PerkUIController.OpenUI`、`WindowsHandler.current.visibleWindows` 和目标窗口自己的初始化方法。补丁在对象出现后执行；如需要延迟帧，设定可观察的完成条件与重试上限。
2. 用稳定名称或组件标记查是否已注入。再次打开窗口只更新图标和状态，不能再次克隆、重复绑定点击事件。
3. 插入图标时先按 [图像示例](sprites-and-icons.md) 取得缓存 Sprite，再把 `Image`/游戏专用图片组件接到正确的父节点，按相邻控件核对锚点、布局、缩放和层级。

## 控件类型

| 需求 | 做法 | 常见失败点 |
| --- | --- | --- |
| 只显示图标/状态 | 绑定图像及可选 tooltip；源状态变化时刷新 | UI 重建后仍引用旧节点 |
| 可点击按钮 | 复用同类按钮预制件/样式，注册一次回调，执行前再验证玩家与目标状态 | 重开窗口导致双击回调、旧回调持有已销毁对象 |
| 扩充 Perk/物品列表 | 在列表源注册内容，再建立对应元素 | 只补 UI 而游戏数据列表未注册 |
| 滚动容器 | 现有内容包进 viewport/`ScrollRect`，设置裁切与滚动条；保留原选择与导航 | 游戏原布局尺寸或对象名变更 |

## 物品 Tooltip

只需追加物品说明时，先核对 `ModHook.OnCreateTooltipEarly/Late(Action<RichTextBuilder, GameItem>)`，通常无需克隆 UI 或补丁整个 Tooltip 生成方法。按自己的物品 ID/标签过滤，读取当前物品状态，向传入的 builder 追加短文本；不要清空其他 Mod 已写的内容。回调可能随悬停频繁执行，避免每次扫描库存、查文件或反复创建资源。保存订阅的委托实例，停用时用同一实例退订；验证多 Mod 同时追加时的顺序与重复行。

## 输入与释放

鼠标事件只处理命中自己的区域。窗口关闭或场景切换时取消订阅，丢弃已销毁的 Unity 引用；对象真正由游戏复用时可以保留标记并在下次打开刷新。不要每帧扫描全场景寻找控件。

## 验证

打开、关闭、再打开、切换分辨率和语言；检查图标遮挡、滚动、tooltip、键鼠输入及回调次数。用运行时层级确认当前对象真实存在，静态资源或补丁类存在不足以证明显示成功。
