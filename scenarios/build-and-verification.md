# 场景：构建、安装核对与生效排查

适用：编译或打包 Mod，核对安装，排查“没生效”、旧版本或加载错误，或汇报分阶段验收结果。先确认目标游戏、项目路径和本次授权范围；构建、安装和启动分别执行。

## 选择构建入口

先读当前仓库约定、构建脚本、参数和依赖声明，包括默认是否打包、写游戏目录或清理旧产物。普通代码修改只构建相关项目并执行必要的已有检查；不为方便而调用会额外打包/安装的总入口。内容 Mod 依赖 Forge 时，调用者引用同一份已选框架产物，避免各自重建共享输出；需要时显式传 `-p:ForgeAssemblyPath='<配套框架路径>'`。

明确要求整套本地打包，且项目采用 `mods-melonloader/Build-ForgeMods.ps1` 时，从内容仓库根目录执行：

```powershell
.\mods-melonloader\Build-ForgeMods.ps1 -GameDir '<实际游戏目录>' -NoInstall
```

本轮脚本默认会安装；`-NoInstall` 才将本次调用限制为检查、编译和本地打包。后续仍以实际参数与实现为准。只打包某个发布组时使用项目指定的专用入口，不能用普通 `bin/Release` 产物冒充混淆发布包。新增调用者是否被总入口覆盖要查脚本清单。

改公共 API 后用 `rg` 查全调用点、示例、检查工程、依赖和打包引用并同步更新。入口不适用于所有游戏内置内容包或独立插件。发布说明从维护源生成，先改维护源；不要只改下次构建会覆盖的 `dist` 副本。

按改动运行有意义的领域检查和签名检查。资源事务需要覆盖输出拒绝、写入失败与恢复；仅文案或图像调整使用文件、资源与布局检查，不为它们新增镜像实现的测试。相关检查通过后，只有新改动或未解决问题才扩大检查范围。

本地开发默认日志等级沿用项目约定，统一入口通常为 `INFO`；项目明确覆盖为 `WARN` 等级时保留其选择。需要已有诊断探针时显式传 `-DefaultLogLevel DEBUG`，不把临时探针变成正常热路径。保留 `MelonPreferences.cfg`，构建默认等级不能证明旧偏好或当前进程采用了新值。

## 安装与当前进程

仅在本次请求包含安装或已有明确授权时写游戏目录；普通构建和本地打包不等于安装。检查实际脚本的安装默认值、复制清单和旧文件清理范围，不假定必须有 `-Install` 才会写游戏目录。

安装前确认目标游戏进程已经停止；不擅自结束用户正在玩的游戏。只更新选定程序集、资源和依赖，保留用户配置与存档。按内部程序集身份和版本核对实际被选中的产物，不只看文件名或修改时间。

MelonLoader 0.7.3 对相同程序集名称选择最高程序集版本，多个旧版本文件存在不等于重复运行；同版本不同内容或其它加载器规则仍需查本次日志。是否清理旧文件按项目安装策略，不把“只能留一份”当通用要求。

常规可重建产物替换不创建额外备份。需要覆盖无法恢复的数据时才保留必要恢复材料。先用路径、程序集身份、版本与日志核对；确需证明候选/发布/安装文件内容相同，或脚本本身有一致性检查时再比较哈希，不默认生成 SHA-256 清单。

磁盘替换不改变已运行进程中的程序集。已有日志可用于诊断，但运行结论只适用于其中记录的启动时间、游戏构建与加载产物。重新启动属于原生执行范围，按下文触发规则处理。

## “没生效”的排查顺序

从最早缺证据的阶段继续，不凭推测重复改规则或扩大补丁。

| 阶段 | 需要的证据 |
| --- | --- |
| 规格与实际规则 | 最新需求进入实际计算路径；旧倍率、批次数或时间规则没有仍被调用 |
| 编译 | 相关检查结果、实际引用的游戏/框架产物和编译结果 |
| 打包（有请求时） | 项目发布入口、混淆/资源/依赖完整，维护源与发布副本一致 |
| 安装（有请求时） | 实际游戏路径、程序集身份/版本、加载选择；需要时检查文件一致性 |
| 加载与注册 | 当前进程日志中的版本、依赖、owner、必需钩子以及逐项 `Applied` / 失败原因 |
| 实际玩法 | 正确触发路径与前后资源、状态或 UI 变化；不仅是提示文字或能力为 true |
| 持久结果 | 正确槽位文件回读，以及新的加载过程恢复相同结果 |

修改 `BuildConfig` 后还要检查现有 JSON、偏好或周目 `ConfigSnapshot` 是否覆盖默认值；见 [配置](config-and-localization.md)。已有周目继续使用其快照时，不用直接覆盖存档来验证默认值。

拖放异常按 [交互](item-interactions.md) 检查实际堆栈与候选槽；机器不产出按 [机器](machines-and-recipes.md) 分别检查准入、配方、材料、输出空间、电量与夜间调度。补丁安装日志只能证明补丁阶段。

## 原生测试触发规则

只有用户明确要求在 Probably Stolen／Nicokobo Forge 中**执行**原生测试，例如“帮我原生测试”“需要帮我原生测试”，或显式点名 `$probably-stolen-native-test`，才读取当前环境的 `probably-stolen-native-test/SKILL.md` 并按其流程执行。讨论原生测试、引用触发语句或要求创建／整理技能均不触发；普通开发、修复、编译和一般测试不预先读取或自动运行该技能。

测试对象不明时先澄清对象，不启动游戏。技能缺失时报告并暂缓原生测试，继续可独立完成的开发检查。有执行请求时使用新游戏进程和可丢弃测试档，按对应场景核对正常路径及相关失败路径，并分别记录加载、输入、消耗、输出、电量、文件回读与保存重载。

## 交付

报告具体变化和已经获得的证据，只列与任务有关的待验收项。领域检查、编译、发布包和文件一致性不能代替游戏内效果；内存写入或保存请求不能代替持久读回。历史记录注明其产物与日期，尚未实测的效果保持待验证。相关检查通过且满足本次范围后停止，不追加无关全套检查、报告或自动发布。
