# 场景：对接其他扩展的可选 API

适用：向已安装的目录、手机/工具面板、角色或物品运行时注册内容，或为其它扩展提供回调。只有实际存在可用扩展接口时才使用；不为可选功能引入强制崩溃依赖。

先区分必需前置和可选联动。项目已经把 Forge 作为必需依赖时，按 [Forge 接入](forge-integration.md) 声明版本并构建，不把缺框架伪装成可选成功。确为可选依赖时，检查程序集装载和类型解析边界；带强类型引用的代码不能只靠入口 `try/catch` 就保证依赖缺失时仍能加载。

## 消费别人的接口

1. 查已加载程序集及版本、公开类型/方法的完整签名、委托类型和调用时机。不要凭名字或参数数量猜测兼容；不存在时只停用对应能力。
2. 在接口和本方内容都就绪后注册稳定 ID、数据/操作回调、图标与刷新回调。重复调用应更新或跳过自己的注册，不覆盖其它扩展的 ID。
3. 注册成功只说明对方接收了声明或回调；查询逐项应用结果及所需能力后，才开放依赖它的玩法。整组提交只解决声明冲突，不代表目录应用或工厂创建也是原子的。实际打开界面、创建内容或执行操作仍要测试。为可选注册设有上限的重试及明确日志，不能每帧反射无限探测。

给已有机器追加配方时，使用目标的公共注册入口并确认目标声明已存在；同时检查输入准入、生产倍率与当前机器耗电，不能只加入一条配方文本。追加声明以一次性合法加载回调为主，见 [机器](machines-and-recipes.md)。

## 提供自己的接口

把纯数据定义、触发条件、奖励/动作回调和事件通知分开。注册时校验 ID 冲突、版本与引用资源；卸载或重载时仅撤销自己的注册。调用第三方回调前保护本功能状态，异常时给出来源与失败结果，不让一次失败污染全局队列。

## 必需钩子与可选钩子

把必需补丁归为一个功能组，缺失时停用整组；能安全撤销时只撤销本组补丁，否则让已装钩子通过统一就绪门控保持惰性。可选接口失败只关闭对应子功能。运行时检查 Harmony owner、接口调用和实际 UI/内容效果，记录兼容的版本范围。

## 验证

分别在依赖存在、缺失、版本不符和重复加载时检查行为；对不同能力分别验证声明、应用和调用。确认基础功能仍可用，日志可解释被停用的部分。
