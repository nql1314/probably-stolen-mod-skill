# 场景：自定义机器、配方与加工

适用：注册可摆放机器，增加电池/材料/产物槽，执行即时或跨夜加工，或给已有机器增加升级与液体处理。

## 内容与运行逻辑分开

定义机器物品 ID、模板、槽位类别、容量/功耗、配方输入、输出、时间、解锁条件和图像。项目已有声明式内容运行时就先用其 schema；只有加工步骤、界面或原生 API 不足以表达时才加 C# 行为。资源和引用 ID 在运行前统一校验。

## 创建机器

1. 等目标目录初始化后注册工厂，基于当前构建已验证的机器模板创建独立实例。建立内部槽、窗口、回调和可保存标签，检查形状、所有权、模块/电池限制。
2. 若窗口会在读档时重建，恢复槽和按钮绑定；避免旧 Unity 引用被继续使用。自定义窗口可参考 [界面注入示例](ui-injection.md)。
3. 把机器状态按“物品实例”保存，不能只按机器类型 ID 缓存。升级上限、耐久、进度和容量统一使用明确单位。

## 一次加工的执行顺序

先只读检查机器仍存在、配方解锁、材料数量、目标容量、电量/燃料、输出落点。确定全部可满足后再执行消耗与产出，并逐步核对实际返回值；游戏 API 无事务时准备失败补偿或可重试的待交付记录。跨夜加工在实际 `EndNight`/醒来入口中择一结算，按“存档槽 + 周目 + 游戏日 + 机器实例”去重，避免同晚执行两次。

液体处理要写清 ml/L 转换、来源所有权、过滤前后污染量和滤芯耐久；耐久应按实际处理量扣减。机器升级的材料消费遵循 [交互示例](item-interactions.md)。

## 验证

新建、摆放、加工、断电、材料不足、产物槽满、保存重载、跨夜重复回调；读回材料、输出和机器进度。配方数据可解析不能证明产物已交付。
